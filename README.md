# MyTool

요양기관의 지점 정보, 로그인, 문서 작성 및 반복 업무를 한곳에서 처리하기 위한 Windows 데스크톱 도구입니다.

현재 구현 기준: 2026-09-09. PySide6 기반 업무 화면, 출근부 분석 모델, 엑셀 데이터 정렬 프로젝트를 포함합니다.

## 프로젝트 구성

| 프로젝트 | 위치 / 실행 | 주요 기능 |
| --- | --- | --- |
| 요양원 업무툴 | `main.py`, `ui/pages/` / `python main.py` | 지점·로그인 관리, 문서 생성, 개인 업무, 정보 조회, 웹 자동화 |
| 사업기획 | `business_planning/`, `ui/pages/business_plan_page.py`, `ui/pages/committee_minutes_page.py` / 앱의 `사업기획` 메뉴 | 사업계획 관리·계정과목별 연간 산출내역, 운영위원회 회의록 입력·AI 초안·이력·DOCX 출력. [상세 안내](business_planning/README.md) |
| 출근부 분석 모델 | `attendance_analysis/` / 앱의 `문서 분석 > 출근부 분석` 또는 CLI | 이미지·정답 데이터 학습, 출근부 이미지 분석, XLSX 결과 저장. [상세 안내](attendance_analysis/README.md) |
| 엑셀 데이터 정렬 | `excel_data_sort/` / 앱의 `문서 분석 > 엑셀 데이터 정렬` 또는 `python -m excel_data_sort` | XLSX·XLS를 JSON 양식에 따라 정규화하고 정형 Dataset으로 변환. [상세 안내](excel_data_sort/README.md) |

## 실행 환경

- Windows
- Python 3.10 이상
- 한글 문서 자동화 기능 사용 시 한컴오피스 한글 설치 필요
- Word 문서의 PDF 변환 기능 사용 시 Microsoft Word 설치 필요
- 출근부 모델 학습·분석은 PyTorch를 사용하며, CUDA 사용 가능 시 GPU를, 그 외에는 CPU를 사용합니다.
- 엑셀 데이터 정렬은 XLSX에 `openpyxl`, XLS에 `xlrd`를 사용합니다. 이 기능에는 Microsoft Excel 설치가 필요하지 않습니다.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python main.py
```

프로젝트의 텍스트 파일과 JSON 데이터는 UTF-8을 사용합니다.

## 메뉴 구성

- 왼쪽 대메뉴를 클릭하면 하위 메뉴가 펼쳐지거나 접힙니다. 시작 시에는 로그인툴이 배치된 대메뉴만 펼쳐집니다.
- 하위 메뉴를 클릭하면 오른쪽에 업무 탭이 열립니다. 이미 열린 업무는 기존 탭으로 이동합니다.
- 탭을 전환해 여러 업무를 오가며 작업하고, 탭을 드래그하여 순서를 바꿀 수 있습니다.
- 탭 영역 오른쪽의 `모든 탭 닫기` 버튼으로 열린 탭을 한 번에 닫습니다. 입력값과 진행 중인 작업은 유지되며, 메뉴에서 다시 열 수 있습니다. 열린 탭이 없으면 버튼은 비활성화됩니다.
- 탭 닫기는 화면만 숨깁니다. 앱 종료 전까지 입력값과 진행 중인 작업을 유지하며 메뉴에서 다시 열 수 있습니다. 탭 닫기는 저장이나 작업 취소를 대신하지 않습니다.
- 앱 종료 시 기존의 진행 중인 작업 및 회의록 변경 확인을 유지합니다. 열린 탭 목록과 순서는 다음 실행 시 복원하지 않습니다.

아래는 기본 메뉴 구성입니다. `설정 > 메뉴관리`에서 대메뉴 이름과 배치를 바꾸면 실제 메뉴는 저장한 구성으로 표시됩니다.

### 메뉴관리

- 기본 위치는 `설정 > 메뉴관리`입니다. 메뉴관리 자체도 다른 대메뉴 아래로 이동할 수 있습니다.
- 대메뉴 추가·이름 수정·삭제, 대메뉴와 하위 메뉴의 위/아래 순서 변경을 지원합니다.
- 하위 메뉴를 선택하고 `이동할 대메뉴`를 고른 뒤 `선택 메뉴 이동`을 누릅니다.
- 대메뉴 삭제 시 그 아래 메뉴는 선택한 다른 대메뉴로 이동합니다. 이동 대상이 삭제할 대메뉴이면 첫 번째 다른 대메뉴로 옮깁니다. 마지막 대메뉴는 삭제할 수 없습니다.
- `메뉴 구성 저장`을 누르면 왼쪽 메뉴에 즉시 적용하고 재실행 후에도 유지합니다. 열린 업무 탭과 입력값은 유지합니다. 저장 전 편집 내용도 탭 이동 시 유지하지만 앱 종료 시에는 저장되지 않습니다.
- 실제 업무 페이지의 추가·삭제·이름 변경 기능은 제공하지 않습니다. 코드에서 새 페이지를 `main.py`의 `menu_groups`에 등록하면 다음 실행 시 관리 대상에 자동으로 추가됩니다. 페이지 인스턴스는 고유한 `self.*_page` 속성으로 생성하며 기존 속성명은 저장 식별자로 유지합니다.
- 새 페이지는 기본 대메뉴에 추가되며, 사용자가 그 대메뉴 이름을 바꿨더라도 기존 배치를 유지합니다. 기본 대메뉴를 삭제한 경우 필요한 대메뉴를 다시 추가합니다.
- 구성은 `data/runtime/menu_layout.json`에 UTF-8로 저장하며 기본 설정은 `data/defaults/menu_layout.json`입니다. 손상된 설정은 덮어쓰지 않고 기본 메뉴로 열며, 메뉴관리에서 오류를 표시하고 저장을 중지합니다.

### 필수도구

- 로그인툴: 지점별 공단·케어포 로그인 및 대표자별 희망이음 로그인 실행
- `희망이음` 유형을 선택하면 이찬재·이샛별·박은경 대표자 버튼만 표시합니다. 같은 대표자의 사업장은 대표자 버튼 하나로 로그인하며 기관기호나 사업자 인증서를 사용하지 않습니다.
- 희망이음 접속 전에 해당 사이트의 `이 기기의 다른 앱 및 서비스에 액세스` 권한을 자동 허용하고 로그인 절차를 시작합니다. 허용 범위는 희망이음 사이트와 실행한 자동화 브라우저 세션입니다.
- 초기 공지 팝업은 실제 표시된 것만 위에서부터 닫고 온라인 백신 설치 요청의 지정 버튼도 클릭한 뒤 로그인합니다. 팝업이 없으면 바로 진행하고, 로딩 마스크 등으로 클릭이 막히면 기존 30초 대기 범위에서 재시도합니다. 팝업 버튼 XPath는 `data/hope_selectors.json`의 `popup_close_buttons`에서 관리합니다.
- 희망이음은 브라우저 생성 → 보안 프로그램 설치 → 희망이음 URL 접속 → 로그인 순서로 진행합니다. 다운로드 폴더의 최신 `nos_setup*.exe`를 사용하며 최초 실행 전 설치 파일이 다운로드되어 있어야 합니다. 파일이 없거나 설치 중 오류가 발생하면 브라우저를 유지하고 중지합니다. 사용자가 마지막 창을 닫으면 자동화 프로세스를 정리합니다.
- `nos_setup (32).exe`처럼 숫자가 붙은 파일도 지원합니다. 이미 열린 nProtect 설치 창이 있으면 새 설치 파일을 중복 실행하지 않고 이어서 처리합니다. 설치 창이 관리자 권한으로 실행되어 버튼 제어가 거부되면 MyTool도 관리자 권한으로 실행하거나 현재 설치 창에서 직접 완료해주세요.
- `data/hope_selectors.json`의 `auto_install_security`는 기본 `true`입니다. 다운로드 폴더의 설치 파일 크기가 안정되고 부분 다운로드 파일이 없는지 확인(최대 10초)한 뒤 유효한 INCA Internet 전자서명을 검증하고 실행합니다. `pywinauto`로 `동의함`·`다음`·`설치`·`마침/완료/닫기`를 처리하며 단축키가 붙은 버튼명도 지원합니다. 완료 화면 또는 완료 버튼을 확인하고 설치 창이 닫히면 URL로 이동합니다. 완료 대기는 최대 300초이며 Windows 관리자 권한 요청은 직접 승인해야 합니다. 의존성은 앱을 실행하는 Python 환경에서 `python -m pip install -r requirements.txt`로 설치합니다. 사이트에서 설치 안내가 다시 나타나면 반복 설치하지 않고 오류를 안내합니다. 직접 설치하려는 경우에만 이 설정을 `false`로 바꿉니다.
- `지점관리 > 희망이음 대표자 설정` 탭에서 대표자별 로그인 ID·비밀번호·인증서명·인증서 비밀번호를 설정하고 저장합니다. 대표자 계정은 지점 정보와 별도로 `data/runtime/hope_accounts.json`에 UTF-8로 저장하며 기존 설정과 동일하게 로컬 JSON에 보관됩니다. 백업 시 이 파일도 포함하세요.
- 기본 대표자명·ID·인증서명은 제공하지만 배포 기본 데이터에 비밀번호를 포함하지 않습니다. 새 PC에서는 두 비밀번호를 입력해야 합니다. 로그인 비밀번호와 인증서 비밀번호는 각각 설정할 수 있습니다.
- 희망이음은 ID·비밀번호 로그인 후 설정한 인증서명과 정확히 일치하는 인증서를 선택하여 비밀번호 입력·확인 클릭을 수행합니다. 인증서는 해당 PC에 설치되어 있어야 합니다. 로그인 주소와 XPath는 `data/hope_selectors.json`에서 관리합니다. 완료 로그는 확인 버튼 클릭까지의 자동화 완료를 뜻합니다.

### 사업기획

- 예산편성: 예산총괄표에서 세입·세출의 관·항별 당해년도 금액을 확인하고, 예산서내역에서 관·항·목별 금액과 사업명 버튼을 조회합니다. 버튼을 누르면 사업 요약과 산출식을 표시합니다.
- 사업계획: 구분·사업명·목표·주기·제공횟수·세부내용 입력, 목록에서 여러 사업 추가·수정·삭제 및 검색
- 발생 시 시행하거나 주기를 확정하지 않은 사업은 `수시`·`미정`으로 저장하며 연간횟수를 임의 계산하지 않습니다.
- 계정과목을 여러 행 추가하고 수량·단가 등 계산 항목을 곱해 연간 산출식과 세입/세출 예상액을 표시합니다. 기본 사업기간은 1년이며 상세 기준은 [사업기획 안내](business_planning/README.md#사업계획)를 참고하세요.
- 운영위원회 회의록 작성: 지점·분기·제목·회의일자·시작/종료시간·장소와 참석자를 입력
- 필수 입력 항목은 `*`로 표시합니다. 프롬프트는 AI 작성 시, 회의록 내용·확인 체크는 최종 문서 저장 시 필수이며, 일반 저장은 지점만 선택해도 가능합니다.
- 프롬프트 한 칸에 참석자 역할·말투·회의 내용을 적으면 대화형 회의록 생성. 전체 결과를 한 칸에서 수정
- 지점별 명단·이력 저장 및 복원, AI 원본 초안 보관, 재생성 전 교체 확인. 기존 안건형 이력도 내용 보존하여 불러오기
- 내장 AI Qwen3-0.6B를 PC 내부 CPU에서 실행. 외부 AI 서버·API 키·호출 요금 없이 작성
- `python -m pip install -r requirements-local-ai.txt` 설치 후 `AI 설정 > 내장 모델 다운로드` (약 1.5GB, 최초 1회)
- 모델 다운로드 후 오프라인 작성, 진행 상태·취소·등록 발언자 및 대화 형식 검증 지원. 회의 내용은 외부로 전송하지 않음
- 실제 회의 내용 검토 확인 후 미리보기·DOCX 출력. 원본의 항목 구조와 별도 빈 서명 목록을 재구성하며
  HWP 원본의 정확한 서식 보존 및 직접 HWP/PDF 출력은 지원하지 않음
- 데이터: `data/runtime/business_planning/`의 `meetings/`, `rosters.json`, `models/`;
  문서 기본 위치: `outputs/`. 원본 및 기존 출력 파일은 덮어쓰지 않음

사용 방법과 원본 양식 분석·출력 제한은 [사업기획 README](business_planning/README.md)를 참고합니다.

### 문서작성툴

- 문서작성툴: `document` 폴더에서 HWP와 DOCX 양식을 함께 관리합니다. 파일명 앞의 `[한글]`·`[Word]` 마크로 구분하며 설정·생성·엑셀 기능은 동일하게 제공합니다.
- `폴더 열기`는 선택 질문 없이 공통 `document` 폴더를 엽니다.
- 기존 `document_hwp`의 한글 양식과 `maked` 결과는 처음 확인할 때 공통 폴더로 복사합니다. 이전 폴더는 백업으로 보존하며 이후 양식 수정·추가는 `document`에서 합니다. 같은 이름의 양식은 공통 폴더의 파일을 우선하고, 서로 다른 기존 생성 결과는 번호를 붙여 보존합니다.
- 파일명을 유지하므로 기존 필드 설정·프리셋·최근 작성 이력은 그대로 연결됩니다. 이전 기록은 `data/runtime/document_folder_migration.json`에 저장하여 통합 후 삭제하거나 수정한 파일을 이전 사본으로 복원하지 않습니다.
- 테이블 목록 관리: 문서 필드에서 선택할 공통 목록 관리

문서 목록에서는 다음 작업을 지원합니다.

- 설정: 누름틀 또는 콘텐츠 컨트롤별 입력 형태와 기본값 설정
- 생성: PDF 또는 원본 형식(한글 HWP / Word DOCX)을 선택하여 입력값을 적용한 새 문서를 각 원본 폴더의 `maked` 하위 폴더에 생성합니다. 취소하면 생성하지 않으며 원본 파일은 수정하지 않습니다.
- 엑셀다운: 일괄 생성용 XLSX 양식 저장
- 엑셀업로드: 저장 형식을 한 번 선택한 뒤 XLSX 각 행을 이용한 문서 일괄 생성

문서 생성 편의 기능:

- 최근 작성 3건: 문서별 최근 제목, 지점 선택, 입력값을 불러와 재사용
- 필드 프리셋: 입력값 묶음 추가·복사·삭제, 적용할 필드 열 제외·복원, 생성 화면에서 `빈칸 채우기` 또는 `전체 적용`
- 엑셀 양식: 첫 열에 지점 선택, 필드명과 입력 형태가 포함된 헤더, 기본값 예시 행, 지점·테이블 목록·체크값 드롭다운 제공
- 지점의 값, 폴더 이미지, 다른 필드를 기준으로 계산하는 날짜·숫자는 엑셀 입력 열에서 제외하고 생성 시 계산
- 문서 생성 진행 상태 표시 및 동일한 PDF·HWP·DOCX 파일명에 번호를 붙여 기존 결과 보존

엑셀 양식의 둘째 행은 기본값 예시이므로 실제 생성할 값으로 수정하거나 삭제한 뒤 업로드합니다. 문서 필드 설정이 바뀌면 `엑셀다운`으로 새 양식을 받습니다.

- ‘컬럼 정리’의 ‘생년월일 조정’은 날짜·두 자리 연도·연월일 숫자·점/슬래시/한글 날짜를 `yyyy-mm-dd` 문자열로 통일합니다. 두 자리 연도는 실행 연도 기준 최근 100년 또는 모두 19xx 중 선택하며, 인식할 수 없거나 존재하지 않는 날짜는 오류로 안내합니다.
- ‘컬럼 정리’의 ‘생년월일 조정’은 날짜·두 자리 연도·연월일 숫자·점/슬래시/한글 날짜를 `yyyy-mm-dd` 문자열로 통일합니다. 두 자리 연도는 실행 연도 기준 최근 100년 또는 모두 19xx 중 선택하며, 인식할 수 없거나 존재하지 않는 날짜는 오류로 안내합니다.
- 추가 컬럼의 참조 셀에 `T4,W4`처럼 여러 주소를 입력하면 값을 순서대로 합칩니다. ‘합칠 때 구분자’로 하이픈·공백 등을 지정할 수 있고 빈칸이면 바로 붙입니다. 빈 셀은 건너뜁니다.
- 헤더행·데이터 시작/끝행, 기준 테이블의 열 범위, 사용할 컬럼·출력 컬럼명, 병합값 처리, 숨김 행·열·시트, 테이블·시트 합치기 기준을 화면에서 설정합니다.
- 생계급여 지급내역처럼 헤더와 한 건의 데이터가 각각 두 행이면 ‘한 건의 행 수 (헤더·데이터)’를 2로 지정합니다. 위·아래 행의 항목을 별도 컬럼으로 펼쳐 한 건을 한 행으로 출력합니다. 제공된 생계급여 지급내역 양식은 헤더 1행, 데이터 시작 3행, 종료 값 ‘합계’로 설정되어 있습니다.
- 양식은 `data/excel_templates/<양식명>.json`에 저장합니다. 예: `노인급여.json`, `생계급여.json`, `출근부.json`.
- 원본을 수정하지 않고 병합 해제 → 빈 행 제거 → 빈 열 제거 → 숨김 옵션 적용 후 반복 헤더를 찾아 실제 데이터와 지정 컬럼을 추출합니다.
- 기본적으로 중간 빈 행을 건너뛰고 값이 있는 마지막 행까지 추출합니다. 컬럼 설정과 미리보기의 값은 가운데 정렬합니다.
- 가로·세로 반복 테이블과 같은 헤더를 가진 시트를 합치거나 따로 출력할 수 있습니다. 원본 미리보기와 설정 변경 시 자동 갱신되는 Dataset 결과를 제공합니다. 양식 저장 버튼은 상단에 있습니다.
- 날짜 헤더는 월별 요일 변경을 허용하며, 처리 내역에서 자동 인식 후보별 점수와 누락 헤더·실패 사유를 확인할 수 있습니다.

### 테스트중

- 공단툴
- 공단툴은 `청구 명세서 만들기`, `장기근속수당 입력하기` 작업과 작업 추가·삭제 및 매크로 설정을 제공합니다. 청구 자동화에는 대상자 생성과 대상자별 명세서 자동 처리 흐름이 구현되어 있습니다.
- 작업을 선택하고 **매크로 복사**를 누르면 저장된 매크로 전체를 새 작업으로 복사합니다. 단계 순서·조건·반복·대기·브라우저 설정을 포함하며 복사본 수정은 원본에 영향을 주지 않습니다.
- **작업 삭제**는 팝업에서 작업을 선택하고 삭제 여부를 확인합니다. 취소하면 변경하지 않으며, 삭제 후에도 매크로 JSON 파일은 보관합니다.
- 작업 추가와 복사는 한글 작업명만 입력합니다. 파일명은 업무 용어를 영문으로 변환해 `federation_selectors_<영문명>.json`으로 자동 생성합니다. 사전에 없는 표현은 고유 식별자를 붙이고 같은 이름은 숫자를 덧붙여 기존 파일을 덮어쓰지 않습니다. 일반 문장 전체를 번역하는 기능은 아닙니다.
- **시작번호**는 기존 테스트 시작번호 위치에서 설정하며 작업별로 저장합니다. 전체 실행은 1이고 개별·다중 지점의 증가 반복에 동일하게 적용됩니다. 매크로 설정 안의 중복 입력칸은 제거했습니다.
- 시작번호 옆 **특정월**은 달력 피커로 선택하며 `YYYY-MM` 형식으로 표시합니다. 저장된 선택이 없으면 현재 날짜의 전월이 기본값입니다(예: 2026-10-29 → `2026-09`, 1월 → 전년도 12월). 선택한 값은 작업별 매크로 JSON의 `selected_month`에 저장되며 작업 전환·재실행 시 복원합니다. 엘레멘트의 **값 입력 (검증)** 보조값에 `{selected_month}`를 넣으면 선택한 월을 입력합니다. 개별·다중 지점 모두 같은 작업별 선택값을 사용합니다.
- 작업 선택 후 실행 도구줄의 **백그라운드 실행**을 체크하면 로그인부터 Chrome headless 모드로 시작하여 인증서 선택·키보드 입력·클릭·스크롤·추출·저장을 화면 없는 브라우저 안에서 수행합니다. 개별·다중 지점에 모두 적용하며 기본값은 해제입니다. 작업별 `browser.headless`에 저장하고, 다음에 시작하는 브라우저부터 적용합니다. 화면 표시 모드와 분리된 `data/chrome_profiles/*_headless/` 프로필과 1920×1080 뷰포트를 사용합니다. 완료 후 외부 Excel 자동 열기를 생략하고 로그에 저장 위치를 표시하며, 개별 실행의 숨겨진 브라우저도 작업 완료·실패 후 종료합니다. 다중 실행은 각 지점 종료 시 기존과 같이 브라우저를 정리합니다. 로그인·작업 실패 시 화면 실행으로 자동 전환하지 않습니다. 실제 공단 인증서/보안 프로그램이 headless 환경을 지원하는지는 해당 PC에서 확인해야 하며, 외부 Windows 창이나 설치 프로그램을 직접 조작해야 하는 사이트 작업은 이 모드로 처리할 수 없습니다.

XPath가 Nexacro/ARIA 그리드의 하위 요소이면 같은 그리드 영역으로 확장합니다. 일반 스크롤은 맨 위로 한 번에 복귀한 후 화면 높이의 80%씩 이동합니다. 공단의 별도 스크롤바는 화면의 행 수에 따라 휠 1~6회를 한 묶음으로 보내며, 위로 복귀할 때는 8회씩 보냅니다. 아래로 수집할 때는 겹치는 행 구간을 남기도록 묶음 크기를 조절합니다. 추출 전용 상태 확인 간격은 0.1초이며, 행 갱신이 안정되면 바로 다음 묶음으로 진행합니다. 클릭·값 입력의 기존 대기 간격은 유지합니다. 화면별 행 갱신이 안정된 것을 확인한 뒤 겹치는 행 구간만 합치므로 머리글과 중복 화면을 반복 저장하지 않습니다. 스크롤바 경계를 읽을 수 없으면 3회 연속 변화 없음으로 종료하며, 경계를 읽을 수 있는데 중간에서 멈추거나 최대 스크롤 횟수를 넘으면 부분 결과를 완료로 저장하지 않고 오류를 표시합니다. 단계별 JSON의 `scroll`(기본 `true`)로 스크롤 수집을 끌 수 있고 `max_scrolls`(기본 `500`, 위·아래 각 방향 기준)로 횟수 한도를 조정할 수 있습니다. 이 설정은 매크로 편집 저장 시에도 보존합니다. `[table_scroll]` 로그에 누적 행 수를 표시합니다. 이미지 자체를 엑셀에 복사하지는 않으며 이미지에 대체 텍스트가 있으면 텍스트를 저장합니다. 머리글이 XPath 밖이면 임의 제목을 추측하지 않고 `열 1`, `열 2` 등으로 저장합니다. 한 작업 실행의 모든 추출 표를 하나의 XLSX에 표별 시트로 누적 저장합니다. 보조값의 출력 이름은 시트 이름으로 사용하고, 중복되거나 Excel에서 허용하지 않는 시트 이름은 자동 보정합니다. 개별 실행의 범위 반복 중 추출한 표도 같은 파일에 새 시트로 추가합니다. 다중 지점 실행은 같은 추출 단계의 데이터를 같은 시트에 누적합니다. 파일은 `data/runtime/macro_exports/`에 지점명·작업명·시각·고유번호로 생성하여 이전 실행 파일을 덮어쓰지 않습니다. 표마다 동일한 실행 파일을 임시 파일을 통한 원자적 저장으로 갱신하므로 이후 단계가 실패해도 이미 추출한 시트는 남습니다. 작업별 JSON의 `export_name`으로 파일 이름 앞부분을 지정할 수 있습니다. 추출값은 실행기의 `extracted_tables`에 단계 키별 `columns`, `rows`, `path`로 보관합니다. `[table_extract]` 로그에서 행·열 수와 파일 경로를 확인합니다. 개별 실행 중 브라우저 종료나 단계 실패가 발생하면 읽은 부분 결과까지 저장하고 XLSX를 자동으로 엽니다. 스크롤 도중 중단한 표는 확인된 행까지만 저장하며 로그의 [table_partial]로 전체 결과가 아님을 알립니다. 추출 데이터가 없으면 파일을 만들지 않습니다. 백그라운드 실행은 기존처럼 자동 열기를 생략하고 저장 위치를 표시합니다. 다중 지점 실행의 부분 결과는 아래 다중 지점 저장 정책을 따릅니다. 열기 실패는 `[table_open]` 로그로 알리며 XLSX 연결 프로그램을 확인합니다.
- **다중 지점 선택**은 월간업무체크처럼 지점 목록을 표시하는 팝업을 엽니다. 업무별로 사용 가능한 지점이 기본 모두 선택되며, 체크를 조정하고 **선택 지점 실행**을 눌러야 시작합니다. 표시된 순서로 로그인 → 매크로 완료 → 브라우저 종료 후 다음 지점을 실행합니다. 로그인·매크로 실패도 기록하고 브라우저 정리 후 다음 지점으로 진행합니다. 브라우저 종료 실패 시에는 다음 지점 실행을 중단합니다.
- 다중 지점의 **테이블 데이터 추출**은 선택한 지점 전체가 실행 파일 하나를 공유하며 같은 추출 단계의 행을 같은 시트에 이어 붙입니다(예: 지점 3개 × 표 7개 → 파일 1개, 최대 시트 7개). 각 시트 맨 앞에 `지점명` 열을 만들고 각 행에 등록된 `branch_name`을 넣습니다. 같은 이름의 다른 추출 단계는 별도 시트로 유지합니다. 지점별 열 순서가 다르면 제목과 같은 제목의 등장 순서로 정렬하고, 추가 열은 뒤에 붙이며 없는 값은 빈칸으로 채웁니다. 행은 지점 간 중복 제거하지 않습니다. 각 표 저장 때 누적 파일을 원자적으로 갱신하고, 일부 지점 실패·중단 시에도 이미 저장된 행을 보존합니다. 다중 실행 종료 후 저장 결과가 있고 열기 동작을 선택했거나 실패·중단이 있었다면 파일을 한 번만 엽니다. 각 지점이 실제 추출한 행만 지점명과 함께 보존하며 미실행 지점은 추가하지 않습니다. 부분 실패가 있으면 결과 요약과 함께 저장된 일부 데이터를 확인할 수 있습니다. 개별 지점 실행은 기존 표별 시트 저장을 유지합니다.
- **현재 지점 완료 후 중단**을 누르면 현재 지점을 마치고 브라우저를 닫은 뒤 멈춥니다. 실행 중 앱 닫기도 같은 중단 요청을 보내며 완료 후 다시 닫을 수 있습니다. 로그에 지점별 성공·실패와 미실행 개수를 표시합니다. 개별 실행 브라우저가 열려 있으면 닫은 뒤 다중 실행을 시작합니다.
- 작업 실행 영역의 **예상치 못한 팝업/얼렛/프롬프트를 닫고 계속 진행**은 작업별로 저장됩니다(기본 해제). 체크하면 요소 탐색 전에 브라우저 alert/confirm/prompt를 확인하고 취소·닫기로 처리한 뒤 탐색을 이어갑니다. 클릭을 가로막거나 탐색 시간이 초과되면 매크로 대상이 없는 표준 dialog 영역의 닫기·취소 버튼을 찾아 닫습니다. 로딩 중인 출력 화면을 보호하기 위해 추가 브라우저 창은 자동으로 닫지 않습니다. 명시적인 alert/confirm/prompt/window 단계와 작업 대상이 포함된 dialog는 유지합니다. 단계별 복구는 최대 3회입니다. `[popup_recovery]` 로그에는 대화상자 내용과 처리 방식이 기록됩니다. 확인을 눌러야 다음 화면으로 진행하는 대화상자는 명시적인 confirm/alert 수락 단계로 설정합니다. 사이트 전용 팝업이나 Windows 파일 선택창 등은 별도 설정이 필요할 수 있습니다.
- 조건부로 나타나는 alert/confirm/prompt는 매크로 설정에서 **확인/수락 (없으면 계속)** 또는 **취소/닫기 (없으면 계속)** 동작을 사용합니다. 지정한 대기시간 동안 대화상자가 나타나면 처리하고, 나타나지 않으면 오류 없이 다음 단계로 진행합니다. 급여 다운로드의 상세조회와 인쇄 사이에는 조회 결과 alert을 위한 조건부 닫기 단계가 기본 설정되어 있습니다.
- 클릭·값 입력 대상이 현재 위치에 없으면 약 1초 뒤부터 열린 다른 창과 중첩 프레임도 같은 대기 제한시간 안에서 탐색합니다. 20초를 모두 소진한 뒤 다시 20초 탐색하는 방식을 제거했습니다. 클릭 가능한 요소를 찾은 창·프레임으로 전환하며 `[target_context]` 로그에 탐색 결과를 남깁니다. 실패 시 대상 이름과 셀렉터를 포함한 오류를 표시합니다. 새 출력 창은 자동으로 닫지 않습니다. 급여 다운로드는 다음 연월 반복 전에 반복 시작 창의 기본 프레임으로 복귀하며 `[range_context]`에 기록합니다.
- 자동 팝업 복구 중 **조회된 대상자 내역이 없습니다.** 알림도 일반 방해 alert과 동일하게 닫고 현재 단계의 대상 탐색을 재개합니다. 다음 화면이 나타나면 현재 매크로와 이후 연월 반복을 계속하며, 대상 요소가 실제로 나타나지 않을 때만 해당 단계의 제한시간 후 오류로 처리합니다. 같은 창·프레임 탐색 결과는 연속해서 반복 출력하지 않습니다.
- 현재 프레임에서 대상을 먼저 확인하고, 출력 프레임이 갱신되면 작업별 `context_scan_interval` 간격으로 열린 창·프레임을 다시 탐색합니다. 급여 다운로드는 0.35초로 설정해 다운로드·저장 버튼 탐색 지연을 줄였습니다. 실패 후에는 최상위 화면이 아니라 원래 프레임으로 복귀합니다. 프레임 위치는 인덱스 대신 프레임 요소와 문서 일치 여부로 확인합니다. `tests/test_federation_browser.py`는 `MYTOOL_CHROMEDRIVER`에 설치된 ChromeDriver 경로를 지정하면 실제 headless Chrome과 로컬 HTML로 지연 로딩 중 불필요한 전환이 없는지 검증합니다. 공단 사이트에는 접속하지 않습니다.
- 케어포툴

테스트중 메뉴는 개발 중인 자동화 기능이므로 실제 업무 적용 전에 결과를 확인해야 합니다.

실행부와 편집 대화상자는 순수 워크플로 모듈을 사용합니다. 편집 저장의 엄격한 구조 검증과 실행 중 필요한 구간만 탐색하는 해석은 기존 허용 범위가 다르므로 별도로 유지하며, 새로운 실행 전 전체 검증이나 action 규칙을 추가하지 않습니다. 기존 `InvoiceProcessor`의 경계 탐색 메서드도 유지합니다. 요소 읽기·대기·조건 및 반복 실행 순서·브라우저 조작은 계속 실행부가 담당합니다.

## 문서 필드 형태

한글은 누름틀 이름, Word는 콘텐츠 컨트롤의 태그를 필드 이름으로 사용합니다. 동일한 이름이 여러 번 나오면 같은 값을 함께 적용합니다.

지원 형태:

- 텍스트
- 날짜: 오늘 또는 다른 날짜 필드를 기준으로 일수 계산
- 숫자: 숫자 검증, 천 단위 쉼표 및 다른 필드값을 기준으로 사칙연산
- 분기: 같은 그룹의 필드 중 사용자가 선택한 하나만 입력
- 그룹: 관련된 여러 필드를 하나의 입력 영역에 묶어 표시
- 다중 체크: 체크 상태 입력 및 한글 양식 체크박스 연동
- 지점의 값: 선택한 지점의 기본 정보 또는 사용자 정의 항목 사용
- 테이블 목록: 테이블 목록 관리에서 등록한 값 선택
- 폴더의 이미지: 다른 필드값과 확장자를 제외한 파일명이 같은 이미지를 찾아 삽입하고 너비·높이를 mm 단위로 지정

## 분기 필드 정책

분기는 여러 누름틀이나 콘텐츠 컨트롤 중 하나만 선택해 값을 넣을 때 사용합니다.

필드 이름은 다음 형식을 사용합니다.

```text
분기_<그룹명>_<항목명>
```

예시:

```text
분기_변경전_대표자
분기_변경전_시설명칭
분기_변경전_시설소재지
```

위 필드는 `분기_변경전`이라는 하나의 그룹으로 자동 인식됩니다.

- 설정 화면에는 `분기_변경전` 아래에 묶인 항목과 각 항목의 입력 설정을 표시합니다.
- 분기 항목 셀렉트박스에는 `대표자`, `시설명칭`, `시설소재지`가 표시됩니다.
- 설정 화면에서 자식 항목별 입력 형태와 기본값을 저장합니다.
- 생성 화면에서는 그룹별 셀렉트 목록에서 이번 문서에 사용할 항목을 직접 선택합니다.
- 생성 화면에서는 선택한 항목에 저장된 입력 형태를 사용해 값을 입력합니다.
- 분기의 자식 형태로 다시 `분기`를 선택할 수는 없습니다.
- 문서 생성 시 선택한 누름틀 또는 콘텐츠 컨트롤만 수정하며, 같은 그룹의 선택하지 않은 필드는 변경하지 않습니다.
- 그룹명과 항목명은 비워둘 수 없습니다.
- 항목명에 밑줄이 포함된 경우 첫 두 구분자 뒤의 문자열 전체를 항목명으로 사용합니다.

그룹 필드는 `그룹_<그룹명>_<항목명>` 형식을 사용합니다. 예를 들어 `그룹_직원_성명`, `그룹_직원_생년월일`은 같은 영역에 함께 표시됩니다. 분기와 그룹은 이름에 적힌 순서대로 결합할 수 있습니다. 예를 들어 `분기_변경전_대표자_그룹_인적사항_성명`은 대표자 선택 시 표시할 그룹 필드이며, `그룹_직원_연락처_분기_종류_휴대폰`은 그룹 안에 분기 선택을 둡니다.

필드 이름이나 그룹·분기 구조를 변경한 양식은 설정 화면에서 각 항목을 확인하고 다시 저장합니다.

## 주요 데이터와 폴더

### Git 기본 데이터와 사용자 데이터 분리

사용자 저장 경로는 실행한 현재 디렉터리가 아니라 프로젝트 루트 기준 `data/runtime/`입니다.
UI, Excel 지점 조회, 공단 실행 스크립트는 공통 모듈 [data_paths.py](data_paths.py)을 사용합니다.
JSON 구조와 화면의 저장·불러오기 동작은 그대로 유지합니다.

| 분류 | 파일·폴더 | Git 정책 |
| --- | --- | --- |
| 기본 데이터 | `data/defaults/*.json` | 추적. 개인정보 없는 빈 지점·메모·업무·이력·사용자 설정, 기본 월간 업무 목록, 기본 수가·인건비율 |
| 사용자 데이터 | `branches.json`, `branch_fields.json`, `branch_task_settings.json`, `memos.json`, `monthly_work_check.json`, `incomplete_tasks.json` | `data/runtime/`에 저장, 제외 |
| 사용자 문서 설정·이력 | `document_field_settings.json`, `hwp_document_field_settings.json`, `document_generation_history.json`, `table_lists.json` | `data/runtime/`에 저장, 제외. 필드 프리셋·입력 기본값도 사용자 데이터 |
| 사용자 수정 가능한 정보·환경 설정 | `service_fee.json`, `labor_cost_ratio.json`, `log_settings.json` | 기본값은 `data/defaults/`에서 추적, 화면에서 변경하는 사본은 `data/runtime/`에서 제외 |
| 사용자 이미지 | 신규 `data/runtime/branch_images/`, 기존 `data/branch_images/` | 모두 제외. 기존 JSON에 기록된 이미지 경로를 보존하기 위해 원본 이미지는 원래 위치에 유지 |
| 로그·캐시·임시 데이터 | `data/login.log`, 기타 `*.log`, `data/chrome_profiles/`, `data/runtime/*.tmp` | 제외. 로그·브라우저 프로필의 기존 위치 유지 |
| Excel 양식 | `data/excel_templates/*.json` | 프로젝트 설정으로 계속 추적 |
| 자동화 작업·매크로 | `data/federation_tasks.json`, `data/carefor_tasks.json`, `data/federation_selectors*.json`, `data/carefor_selectors_work.json` | 프로젝트 설정으로 계속 추적 |
| 추가 자동화 설정 | `data/content_download.json`, `data/get_payexcel.json`, `data/test.json` | selector·browser·timeout 구조의 매크로 설정이므로 추적 유지. `test.json`은 테스트 fixture가 아님 |
| 테스트 fixture | `tests/` 내 테스트 코드·fixture | 계속 추적. 테스트 데이터는 임시 디렉터리에 생성 |

최초 접근 시 해당 runtime 파일이 없으면 같은 이름의 기존 `data/<파일명>`을 먼저 복사합니다.
기존 파일도 없으면 `data/defaults/<파일명>`을 복사합니다. 새 PC에서는 지점·메모·미비 업무와 작성 이력은 비어 있고,
월간 업무 목록 및 수가·인건비율 기본값은 제공됩니다. 사용자 데이터를 기본 파일에 넣지 않습니다.
runtime 파일이 이미 있으면 내용이 비어 있거나 JSON이 손상되어 있어도 초기값으로 덮어쓰지 않습니다.
이전 과정은 바이트 그대로 복사하므로 알 수 없는 필드·공백·문자 인코딩도 보존되며, 읽기 실패 시 기본값으로 대체하지 않고 오류를 전달합니다.
완성된 임시 사본을 하드 링크로 게시해 동시 최초 실행에서도 기존 파일을 교체하지 않습니다(Windows NTFS 등 하드 링크 지원 파일시스템 필요).

**기존 설치 업데이트:** 추적 해제 커밋을 다른 PC에서 pull하면 Git이 깨끗한 기존 추적 파일을 제거할 수 있습니다.
따라서 업데이트 **전에** 앱을 종료하고 기존 `data/`를 별도 위치에 백업하세요.
업데이트 후 백업의 사용자 JSON을 원래 `data/<파일명>` 위치에 없는 경우에만 복원하면 최초 접근 시 자동 이전됩니다.
이미 runtime 파일이 있으면 자동 병합하지 않으므로 두 사본 중 사용할 데이터를 확인해야 합니다.
현재 작업 PC에서는 추적 해제 전에 사용자 JSON 사본을 생성하고, 기존 JSON·이미지 파일은 삭제하지 않습니다.
이 정책은 과거 Git 이력에서 데이터를 제거하는 작업은 포함하지 않습니다.

백업·PC 이전 시에는 `data/runtime/`와 `data/branch_images/`를 함께 보관합니다.
문서 설정에 저장한 외부 이미지·문서의 절대 경로는 기존과 동일하게 사용하므로 새 PC에서는 해당 경로도 확인하세요.
기존 `data/<사용자 파일명>`은 이전 원본으로 남으며 이후 저장은 runtime에만 반영됩니다.
Excel 양식이나 매크로를 편집하면 프로젝트 설정 변경이므로 Git 변경사항이 표시되는 것이 정상입니다.

## 개발 및 문서화 정책

Git 업로드 제외 정책:

- 모든 `maked/` 폴더와 그 하위 폴더에서 생성되는 PDF는 제외합니다. 기존 `document/maked/` 전체 제외 규칙도 유지합니다.
- `.log`로 끝나는 로그 파일은 위치에 관계없이 제외합니다.
- JSON은 용도별로 관리합니다. `data/defaults/`와 프로젝트 양식·자동화 설정은 추적하고, `data/runtime/` 및 이전 사용자 파일은 제외합니다.
- 이미 추적 중인 제외 대상 파일은 로컬 파일을 보존하고 Git 추적만 해제합니다.

- 메뉴, 사용자 기능, 필드 명명 규칙 또는 데이터 저장 정책이 변경되면 같은 작업에서 이 README도 함께 갱신합니다.
- 새 프로젝트·하위 프로젝트가 추가되면 같은 작업에서 루트 `README.md`의 **프로젝트 구성** 표에 이름, 경로, 목적, 실행 방법을 반드시 추가합니다.
- 새 프로젝트의 메뉴, 설치 의존성, 입력·출력 및 저장 경로도 해당 절에 반영합니다. 별도 README가 있으면 루트 README에서 연결하고 두 문서의 설명을 일치시킵니다.
- 문서 파일명은 `README.md`로 통일합니다.
- Python에서 텍스트 파일을 열 때는 `encoding="utf-8"`을 명시합니다.
- Windows에서 테스트하기 전 `chcp 65001`로 코드 페이지를 UTF-8로 변경합니다.
- 사용자 데이터와 작업 중인 변경사항은 기능 수정과 관계없으면 덮어쓰거나 되돌리지 않습니다.

테스트 실행 예시:

```powershell
chcp 65001
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

- 가감산 작업의 근무내용제출은 실제 마우스 클릭 후 근무시간 표 컨테이너가 표시되어야 진행하며 제출을 자동 재시도하지 않습니다. 기타자료관리는 고정 div 순번 대신 팝업 메뉴 ID와 표시 문구로 찾습니다. 입사보고·근무시간은 특정 데이터 행 대신 표 컨테이너를 찾아 빈 표에서도 화면 진입을 확인합니다. 추출 단계의 `skip_empty: true`는 표가 표시된 상태에서 제한시간 동안 데이터 행이 나타나지 않으면 해당 표의 추출·시트 생성을 생략하고 다음 단계로 진행합니다(`[table_skip_empty]`). 가감산의 7개 표에 적용하며, 표 영역 자체가 없거나 화면 이동·브라우저 오류가 난 경우는 계속 오류로 처리합니다.

- 표 수집은 스크롤바가 하단에 도달해도 즉시 종료하지 않습니다. 아래 방향 스크롤과 행 갱신 대기를 반복하여 하단 위치와 데이터 행이 3회 연속 동일한지 확인하고, 늦게 표시된 마지막 행을 병합한 뒤 저장합니다. 하단 판정의 1픽셀 허용 오차도 줄여 끝부분이 남아 있는데 완료로 판단하는 경우를 방지합니다. 검증 중에도 최대 스크롤 횟수 제한은 적용됩니다.

- 가감산 작업은 `performance.context_scope: "current"`로 현재 공단 업무 창·프레임에 고정합니다. 요소가 없을 때 마이블로그 등 다른 창·프레임으로 자동 전환하지 않으며 `[context_pinned]`를 기록합니다. 다른 작업의 기존 문맥 탐색은 유지합니다. 당월운영·근무내용관리는 한 번 클릭 후 다음 화면을 기다리며 자동 재클릭을 해제했습니다. 입사보고·근무시간 표 및 화면 완료 조건은 `npfa100m01` 팝업 내부인지 함께 검사하여 배경 화면의 표를 잘못 추출하거나 근무내용관리 클릭을 잘못 생략하는 경우를 방지합니다. 필요한 메뉴 이동은 유지합니다.
입사보고 화면은 표의 `입력여부` 머리글도 확인하므로 팝업 내 다른 표가 먼저 표시되어 있어도 완료로 판단하지 않습니다.

- 입사보고 추출 대상은 본문의 고정 div 경로 대신 `npfa100m01` 내부의 Grid/ARIA grid 중 `성명`·`생년월일`·`입력여부` 머리글이 함께 있는 표 전체를 찾습니다. 머리글이 본문과 별도 영역에 있거나 줄바꿈·중첩 요소로 표시되어도 찾으며, 같은 대상을 근무내용관리 화면 완료 확인과 추출에 사용합니다.

- 근무내용제출의 근무시간 표는 `npfa100m01` 내부 Grid/ARIA grid의 `성명`·`총계`·`특례` 머리글로 표 전체를 찾아 세로 스크롤바와 데이터 본문을 함께 수집합니다. Nexacro의 여러 줄 머리글은 열별 이름으로 합치고 데이터 행이 나타날 때까지 기다려 머리글만 저장하고 끝나는 경우를 방지합니다.

- 가감산 추출 완료 후 `sort_templates`의 시트별 연결에 따라 문서 분석 > 엑셀 데이터 정렬의 저장 양식을 다시 읽어 기존 변환 엔진으로 정렬합니다. 종사자·근무시간·보험·위탁급식·가산점수·근무인원 양식을 적용하여 원본 옆에 `_정렬.xlsx`를 생성하고 이 파일을 엽니다(백그라운드는 경로만 안내). 다중 지점은 전체 종료 후 한 번 정렬하며 지점명 컬럼을 유지합니다. 생년월일·직종·시간 변환과 선택 컬럼은 등록 양식을 따릅니다. 복합 머리글은 유일한 상위 제목이 일치하는 경우에만 연결하며 양식 파일은 변경하지 않습니다. 연결 양식이 없는 시트는 `원본_`, 변환 실패 시트는 `미정렬_`로 보존하고 로그로 안내합니다.
