# 사업기획 / 운영위원회 회의록

PySide6 화면은 `ui/pages/committee_minutes_page.py`, 저장·AI·DOCX 서비스는
[minutes.py](minutes.py)에 있습니다. 루트에서 `python main.py`로 실행합니다.
사업계획·예산편성은 준비 중 안내만 제공하며 실제 연계 기능은 구현하지 않습니다.

## 사용 순서

1. `사업기획 > 운영위원회 회의록 작성`에서 지점, 분기(1~4분기), 제목, 회의일자, 시작·종료시간과 장소를 입력합니다.
2. 참석자 표에 성명·직책·회의 내 역할을 입력하고 참석 여부를 선택합니다.
   지점 명단 저장/불러오기로 참석자를 재사용합니다. 불참자는 AI 발언 및 서명 목록에서 제외합니다.
3. `프롬프트 / 회의록` 탭에서 참석자의 역할·말투와 회의 내용을 자유롭게 적습니다.
   예: “A는 공손한 진행자입니다. B는 외부 인사로 질문과 감사 인사를 합니다.
   2026년 예산의 적법성을 검토하는 회의입니다. 서로 의견을 주고받도록 작성해 주세요.”
   참석자 표에는 A와 B를 등록합니다. 직책과 역할은 선택 입력이며 프롬프트에 적어도 됩니다.
   개회·폐회와 안건별 상세 입력은 없으며, 생성 결과 전체를 아래 회의록 칸에서 수정합니다.
4. 내장 AI는 Qwen3-0.6B를 MyTool 프로세스 내부 CPU에서 실행합니다. 외부 AI 서버와 API 키는 필요 없습니다.
   최초 설치 시 `python -m pip install -r requirements-local-ai.txt`로 실행 패키지를 설치합니다.
   `AI 설정 > 내장 모델 다운로드`로 약 1.5GB 모델을 공식 Hugging Face 저장소에서 받습니다.
   또는 프로젝트 루트에서 `python -m business_planning.local_ai`를 실행합니다.
5. 다운로드 후 `AI 회의록 작성 / 재생성`을 누르면 인터넷 없이 프롬프트에 맞는 대화형 초안을 작성합니다.
   등록 순서대로 참석자들이 번갈아 말하며, 앞선 발언을 참고해 기본 6회 이상 대화를 생성합니다.
   말투와 역할은 프롬프트를 따르며, 회의록 전체가 완성된 뒤 편집 칸에 반영합니다.
   회의 내용은 외부로 전송하지 않으며 기존 외부 API 설정도 읽지 않습니다.
   CPU 환경에서는 시간이 걸릴 수 있으며 실행 시 메모리 약 4GB 이상 여유를 권장합니다.
   진행 상태와 취소 버튼을 제공하며 취소는 현재 모델 로딩/계산이 끝난 뒤 처리됩니다.
   입력이 너무 길거나 응답 검증에 실패하면 기존 편집 내용을 유지하고 오류를 안내합니다.
6. 생성된 회의록 칸에서 실제 회의 내용·발언·결정사항을 검토하고 수정합니다.
   AI 원본 초안은 저장 데이터의 draft에 별도로 보관합니다.
   등록된 참석 발언자와 발언 교환 형식을 검증하지만 사실의 정확성을 자동 보증하지 않습니다.
   예산 적법성을 심사한다는 요청만으로 적법하다고 결론내리도록 하지 않습니다.
   재생성은 현재 편집 내용을 교체하기 전에 확인합니다. 수정하면 최종 확인 체크가 해제됩니다.
7. 저장으로 미완성 회의도 보관하며 지점별 이력에서 다시 불러옵니다.
   최종 확인을 체크한 뒤 미리보기와 `최종 DOCX 저장`으로 출력합니다.
   기존 파일명은 덮어쓰지 않으므로 새 이름을 지정합니다.

## 원본 분석 및 출력 범위

제공된 HWP 5 형식 문서의 본문과 미리보기 스트림을 읽어 다음 구조를 확인했습니다.

- 제목, 연도·차수, 기관명
- 표 형태의 회의주제·회의일시·회의장소·참석자명
- 개회선언, 안건별 발언, 폐회선언
- 회의결과와 반영내용
- 별도 서명 목록: 주제, 일시, 참석인원, 장소, 연번·구분·참석자·서명

원본에는 이전 회의 내용과 서명 그림이 포함되어 있습니다. 원본을 변경하거나 저장소로 복사하지 않았으며
이전 서명은 새 문서에 재사용하지 않습니다. DOCX는 확인된 항목 구조와 표, 별도 서명 페이지를 재구성합니다.
서명란은 공란입니다. 새 회의는 검토·수정한 전체 회의록만 출력하며 빈 개회·폐회·안건란을 추가하지 않습니다.

**제한:** 이 환경에서 기존 HWP COM 열기가 응답하지 않아 원본 HWP 직접 출력과 정확한 페이지 배치,
글꼴·여백·표 너비·도형 보존을 검증하지 못했습니다. DOCX는 원본 HWP의 완전한 서식 복제본이 아닙니다.
앱 미리보기는 문서 내용 확인용이며 실제 DOCX 페이지 배치는 Word/한글에서 확인합니다.
HWP 직접 출력 및 PDF 출력은 이번 구현에 포함되지 않습니다.

## 저장 구조

공통 `runtime_directory()` 기준 `data/runtime/business_planning/` 아래에 저장하며 Git에서 제외됩니다.

- `meetings/<회의 ID>.json`: 기본 정보, 참석자, 프롬프트(prompt), AI 원본 초안(draft), 편집 결과(final), 확인 상태, 수정시각
- `rosters.json`: 지점별 재사용 참석자 명단
- `models/qwen3-0.6b/`: 고정 버전의 모델·토크나이저·라이선스 (Git 제외)
- 기존 `ai_settings.json`은 보존하지만 더 이상 사용하지 않음
- `outputs/`: DOCX 저장 대화상자의 기본 출력 위치

JSON은 UTF-8이며 임시 파일 완성 후 원자적 교체로 저장합니다. 손상된 기존 파일은 초기값으로 덮어쓰지 않습니다.
지점 식별은 기존 기관기호/지점명 규칙을 사용합니다. 회의·참석자 ID를 유지하며 회계연도는 회의일자의 연도로 기록합니다.
새 입력은 version=2로 저장합니다. 기존 version=1 이력은 열 때 안건 메모를 프롬프트로,
개회·안건별 결과·결정사항·후속 조치·폐회를 전체 회의록으로 변환합니다.
원래 데이터는 legacy_source와 기존 필드에 보존하고, 사용자가 저장하기 전에는 디스크를 변경하지 않습니다.
기존 차수를 분기로 오인하지 않도록 이전 이력의 분기는 회의일자를 기준으로 계산하고 최종 확인 체크를 해제합니다. 현재 실제 사업·예산 연결은 하지 않습니다.
회의 이력은 저장된 회의별 목록이며 동일 회의 저장 시 수정 버전별 백업을 만들지는 않습니다.

## 내장 모델 구현

[Qwen3-0.6B 공식 모델 카드](https://huggingface.co/Qwen/Qwen3-0.6B)를 기준으로
Transformers 4.57.1과 기존 PyTorch를 사용합니다. 모델 버전은
`c1899de289a04d12100db370d81485cdf75e47ca`로 고정하며 Apache-2.0 라이선스 파일도 내려받습니다.
추론은 로컬 파일 전용(`local_files_only=True`), 원격 코드 실행 금지, safetensors 형식으로 수행합니다.
다운로드 작업에만 인터넷이 필요하고 그 작업에는 회의 데이터를 전달하지 않습니다.
모델 파일은 Git에 포함하지 않으므로 새 PC에서는 다시 다운로드하거나 모델 폴더를 복사합니다.
소형 모델은 문장 품질과 사실 정확성에 한계가 있어 최종 검토가 필요합니다.
