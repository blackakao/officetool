# 사업기획 / 운영위원회 회의록

PySide6 화면은 `ui/pages/committee_minutes_page.py`, 저장·AI·DOCX 서비스는
[minutes.py](minutes.py)에 있습니다. 루트에서 `python main.py`로 실행합니다.
사업계획·예산편성은 준비 중 안내만 제공하며 실제 연계 기능은 구현하지 않습니다.

## 사용 순서

1. `사업기획 > 운영위원회 회의록 작성`에서 지점, 회계연도, 차수, 주제, 일시와 장소를 입력합니다.
2. 참석자 표에 성명·직책·회의 내 역할을 입력하고 참석 여부를 선택합니다.
   지점 명단 저장/불러오기로 참석자를 재사용합니다. 불참자는 AI 발언 및 서명 목록에서 제외합니다.
3. 안건을 추가하고 주요 논의, 참석자별 의견, 결정사항, 후속 조치, 참고사항을 작성합니다.
   내용 편집 탭에서 안건별 회의록을 직접 작성할 수 있습니다. 개회·폐회는 별도 탭에서 편집합니다.
4. AI를 사용할 때는 `AI 설정`에서 사용자가 선택한 서비스의 Chat Completions 호환 HTTPS 전체 URL과
   JSON 객체 응답을 지원하는 모델을 입력합니다. 서비스 기본값은 없습니다.
   인증키는 `MYTOOL_AI_API_KEY` 환경변수에 설정하고 앱을 다시 실행합니다.
   인증키는 앱의 설정·회의 JSON에 저장하지 않으며 저장소에 넣지 않습니다.
5. AI 작성 버튼을 누르면 전송 주소·모델·전송 항목·요금 가능성을 확인합니다.
   동의한 경우에만 실제 요청하며 개발 테스트는 모의 응답으로 수행합니다.
   UI는 요청 중 편집을 잠그고 진행 상태를 표시합니다. 네트워크 제한시간은 60초이며
   인증·사용량·연결·응답 오류가 발생해도 입력과 이전 결과는 유지됩니다.
6. AI 원본 초안과 내용 편집 탭을 비교하고 실제 회의 내용·발언·결정사항을 검토합니다.
   AI 결과의 안건 ID와 등록된 참석 발언자를 검증하지만 사실의 정확성을 자동 보증하지 않습니다.
   재생성은 현재 편집 내용을 교체하기 전에 확인합니다. 수정하면 최종 확인 체크가 해제됩니다.
7. 저장으로 미완성 회의도 보관하며 지점별 이력에서 다시 불러옵니다.
   최종 확인을 체크한 뒤 미리보기와 `최종 DOCX 저장`으로 출력합니다.
   기존 파일명은 덮어쓰지 않으므로 새 이름을 지정합니다.

## 원본 분석 및 출력 범위

제공된 HWP 5 형식 문서의 본문과 미리보기 스트림을 읽어 다음 구조를 확인했습니다.

- 제목, 연도·차수, 기관명
- 표 형태의 회의주제·회의일시·회의장소·참석자명
- 개회선언, 안건별 발언, 폐회선언
- 회의결과와 반영내용
- 별도 서명 목록: 주제, 일시, 참석인원, 장소, 연번·구분·참석자·서명

원본에는 이전 회의 내용과 서명 그림이 포함되어 있습니다. 원본을 변경하거나 저장소로 복사하지 않았으며
이전 서명은 새 문서에 재사용하지 않습니다. DOCX는 확인된 항목 구조와 표, 별도 서명 페이지를 재구성합니다.
서명란은 공란입니다. 안건별 결정사항·반영내용은 사용자 입력만 출력합니다.

**제한:** 이 환경에서 기존 HWP COM 열기가 응답하지 않아 원본 HWP 직접 출력과 정확한 페이지 배치,
글꼴·여백·표 너비·도형 보존을 검증하지 못했습니다. DOCX는 원본 HWP의 완전한 서식 복제본이 아닙니다.
앱 미리보기는 문서 내용 확인용이며 실제 DOCX 페이지 배치는 Word/한글에서 확인합니다.
HWP 직접 출력 및 PDF 출력은 이번 구현에 포함되지 않습니다.

## 저장 구조

공통 `runtime_directory()` 기준 `data/runtime/business_planning/` 아래에 저장하며 Git에서 제외됩니다.

- `meetings/<회의 ID>.json`: 기본 정보, 참석자, 안건, AI 원본 초안, 편집 결과, 확인 상태, 수정시각
- `rosters.json`: 지점별 재사용 참석자 명단
- `ai_settings.json`: 서비스 주소와 모델만 저장
- `outputs/`: DOCX 저장 대화상자의 기본 출력 위치

JSON은 UTF-8이며 임시 파일 완성 후 원자적 교체로 저장합니다. 손상된 기존 파일은 초기값으로 덮어쓰지 않습니다.
지점 식별은 기존 기관기호/지점명 규칙을 사용합니다. 회의·참석자·안건은 독립 ID를 가지며 회계연도와
안건별 `business_ids`, `budget_ids` 배열을 예약합니다. 현재 실제 사업·예산 연결은 하지 않습니다.
회의 이력은 저장된 회의별 목록이며 동일 회의 저장 시 수정 버전별 백업을 만들지는 않습니다.
